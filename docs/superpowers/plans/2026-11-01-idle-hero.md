# Idle Hero Implementation Plan

> Execute inline using executing-plans; dedicated new project folder provides isolation.

**Goal:** A playable responsive local idle dungeon webapp matching the visible recording.

**Architecture:** Pure state/economy core; Three.js scene owns rendering and movement; DOM app owns HUD, panels and persistence.

**Tech Stack:** HTML, CSS, JavaScript, vendored Three.js, Node built-in test runner/static server.

## Global constraints

- Folder: `Idle hero dungeon`.
- Desktop and mobile sizes; local only, no deployment.
- No remote runtime dependencies. Preserve other projects.

## Tasks

- [x] 1. Write tests in `tests/core.test.cjs` covering `createState()`, `awardKill(state,boss)`, `upgradeWeapon(state,id)`, `unlockSkill(state,id)`, `restoreState(raw,now)`. Run `npm test` and observe missing-core failure.
- [x] 2. Implement `core.js`: earned-currency transactions must never become negative; invalid skill prerequisites must not spend points; invalid saves return a fresh state. Verify `npm test`.
- [x] 3. Implement `world.js`: faceted grass and snow islands, bridge, trees, houses, hero, enemies, loot and effects. `createWorld(canvas,callbacks)` exposes movement, stats, pause, zone navigation and animation.
- [x] 4. Implement `index.html`, `styles.css`, `game.js`: responsive HUD, joystick, working inventory/skills/shop/stats/settings, minimap, quest rewards, chest drops, local save/export/import.
- [x] 5. Add `server.cjs`, Windows launcher and README. Check syntax, tests and HTTP responses. Use browser UI at desktop/mobile, verify controls and panels, inspect screenshots. Fix observed issues and review.
